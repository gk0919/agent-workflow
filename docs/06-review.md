# Review

Review 检查实现质量。实现者先自审，支持时独立审查。

## Review 输出模板

```md
# Review Report

## 结论
通过 / 有条件通过 / 不通过

## Findings
- [P0/P1/P2/P3] 文件:行 问题说明、影响、建议

## Open Questions
- 

## Test Gaps
- 

## Summary
本次 review 覆盖了哪些方面。
```

## Review 模式

| 模式 | 适用场景 | 要求 |
|------|----------|------|
| Focused Review | Micro Change | 审查任务 patch、根因/验收、兼容、升级条件和目标静态检查 |
| Self Review | 小改动、无 subagent | 实现者按清单自审并记录 |
| Independent Review | 中高风险改动 | 独立执行者审查 |
| PR Review | 异步任务 | 以 diff、测试和 CI 为中心 |

## 检查清单

| 类别 | 检查点 |
|------|--------|
| 逻辑正确性 | 条件分支、状态流转、边界值、默认值 |
| 健壮性 | 空值、异常、接口失败、权限不足 |
| 兼容性 | 旧数据、旧配置、旧入口、浏览器兼容 |
| 性能 | 大列表、循环、重复请求、缓存失效 |
| 内存泄漏 | 事件、定时器、订阅、DOM/组件引用 |
| UI 规范 | 布局、按钮、弹窗、表格、提示、禁用态 |
| 安全 | 权限、敏感字段、输入输出、日志 |
| 可维护性 | 责任层、重复规则/状态、复用边界、扩展成本、局部抽象 |
| 测试 | 当前验收、同类/扩展场景、异常、空数据、权限、旧数据 |
| 可追踪性 | 契约追踪链是否完整，Actual Change 是否与任务 patch 一致 |
| 验证声明 | 各验证主体、能力条件、状态和证据是否真实 |

## 优先级

- P0：数据错误、严重安全问题或核心流程不可用。
- P1：用户可见的严重问题或高概率回归。
- P2：中等风险，合并前修复。
- P3：低风险建议或后续优化。

## 通过标准

- P0/P1 必须修复或明确停止。
- P2 需要修复，或说明暂缓原因。
- 未验证项必须进入 Verify Report。
- 缺少 Goal / AC、Actual Change 或 Test Point 的任务不能以“Review 通过”掩盖追踪缺口。
- Focused Review 发现接口、数据、权限模型、公共链路、异步生命周期、新业务状态、新交互模式或影响范围扩大时，必须退出 Micro Change 并升级完整 Review。

## Agent 产物特别检查

AI agent 生成的改动还要额外检查：

- 是否为了完成任务扩大了改动范围。
- 是否只让当前案例通过，未消除设计根因或维护需求不变量。
- 是否为了少改文件把规则留在错误责任层。
- 是否引入过度抽象、重复分支或不可维护状态。
- 是否遗漏项目规则，只满足了通用代码逻辑。
- 是否修改了生成物、本地配置或用户未授权文件。
- 是否在没有证据的情况下假设接口、字段或业务语义。
- 是否偏离原始记录或伪造来源事实。
