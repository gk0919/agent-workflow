# level-4（L4）

L4 处理跨模块、跨仓库的架构级变更：它改变的是公共契约、数据模型、权限边界、异步生命周期或
发布协同方式，而不是某个位置的行为。由 `--intent architecture` 进入，`direct` 与 `pool` 入口都接受。

## 入口与边界

适用于：

- 公共契约变化：跨模块、跨仓库共享的接口、事件、协议与序列化格式。
- 数据模型变化：需要迁移、回填、双写或状态机调整的数据结构。
- 权限与安全边界变化：认证、授权、租户隔离与审计范围。
- 异步生命周期变化：消息顺序、重试、幂等与补偿语义。
- 迁移与发布协同：需要多个仓库按顺序落地、存在兼容窗口或必须分批切换。

仍应留在 `level-2` 的情况：

- 改动只在单仓库内，且不改变被其他模块或仓库依赖的任何契约。
- 只是"看起来很关键"，但没有公共契约、数据模型或授权边界的变化。
- 需求本身尚不明确。先补齐事实，不要为了绕过不确定性而升级。

边界规则：

- 事实自动升级到 L4 **尚未实现**：不存在"命中事实即自动进入 L4"的路径，必须显式切换 Route。
- 切换 Route 会创建新的 Run，用 `--parent-run-id` 关联原有 Run，保留已经确认的事实。
- 已进入 L4 的工作不因"实际落在单仓库"而自动降级；降级需用户确认并重新评估契约影响。

## 架构评审

架构评审必须逐项给出下列内容，缺少任一维度都不得批准：

1. 不变量：变更前后必须始终成立的性质，以及如何验证。
2. 边界与责任层：改动归属哪个模块与仓库、为什么不能落在更内层。
3. 契约与兼容策略：契约形态、版本策略、兼容窗口，以及不兼容时的处理。
4. 数据模型与迁移：结构、迁移与回填顺序、校验方式、失败后的可恢复状态。
5. 回滚与降级：触发条件、步骤、数据后果与不可回滚点。
6. 被否决的替代方案及理由：至少一个真实备选方案，以及它为什么被否决。

结论标记"等待用户批准"并结束回合：架构决策只能由当前会话用户批准，不得由 Agent 自行决定，
也不得用历史批准、沉默或提问代替确认。批准后才进入里程碑与后续阶段。

## 里程碑

把架构变更拆成可独立验收的里程碑，逐个记录：

- 范围：本里程碑改哪些仓库、哪些契约与哪些数据。
- 依赖：前置里程碑、契约冻结结论和外部条件。
- 验收条件：可观察、可复现的判定。
- 回滚点：本里程碑失败时回到哪个状态，以及此时的兼容性后果。

不允许把"全部完成"当成唯一验收点，也不允许把多个里程碑合并成一个不可分割的验收；
出现无法独立验收的里程碑时，说明拆分仍然过粗，应继续拆分后再批准。

## 多仓库协同

- 契约冻结：先冻结契约再并行落地，冻结结论与时间点写入任务产物；冻结后修改契约需重新评审。
- 落地顺序：按仓库写明顺序、依赖和每个仓库的完成判定，不用一次操作概括多个独立仓库。
- 版本与兼容窗口：明确新旧版本共存期间的行为，以及窗口关闭的条件。
- 跨仓库验证：给出跨仓库的验证方式（契约一致性、端到端路径、数据校验），并逐仓库标注结论。

授权沿用 [`12-artifacts.md#多仓库上下文`](./12-artifacts.md#多仓库上下文) 的按仓库、按动作判定规则：
Read、stage、commit、push 和 PR 授权彼此独立的，也按仓库独立；不得把一个仓库的授权扩展到另一个仓库，
也不得用"同一批变更"作为扩展到其他仓库的理由。多仓库与较大 diff 是 L4 的固有形态，
但它们不改变授权与验证要求。

## 升级与回退

- 升级：执行中发现跨仓库契约、数据模型、权限边界或异步生命周期影响时，停下当前阶段，
  记录触发条件与已确认事实，显式切换到 L4 并就新事实重新评审。
- 回退：只有在用户确认且契约影响被重新评估后才可退回 `level-2`；
  已经落地的里程碑产物与契约冻结结论必须保留，不得因为换 Route 而丢弃。
- 无论升级还是回退，都重新生成 Route Packet 并按新阶段白名单读取，不累计上一阶段的手册。
