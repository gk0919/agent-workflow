# Analyze

Analyze 是分析、调研和代码定位任务的只读阶段。它的目标是用可核对证据回答问题，不修改文件，也不自动进入 Implement 或 Git。

## 输入

- 业务任务的 Source Snapshot。
- Intake Card；简单任务可使用 Intake (lite)。
- 项目地图、目标文件、日志或用户提供的上下文。
- 当前工具实际读取到的证据。

## 输出模板

```md
# Analysis Report

## 问题与范围
- 本次分析要回答什么。
- 明确不分析或不修改的内容。

## 证据
- 文件、行号、配置、日志或来源记录。

## 现状与数据流
- 当前行为、调用关系、状态变化或影响范围。

## 结论
- 已被证据支持的判断。

## 风险与影响
- 兼容、权限、性能、数据、UI 或跨模块风险。

## Open Questions
- 无法从现有证据确认的内容。

## 建议
- 可选后续动作；不得把建议写成已授权实现。
```

## 规则

- 事实、推断和待确认项必须分开。
- 只引用实际读取过的内容，不把工具记忆当作证据。
- 业务分析必须能追踪到 Source Snapshot。
- 用户只要求分析时，不创建代码改动、任务提交或远端动作。
- 需要实现时，必须由用户授权或当前请求明确包含实现，再进入 Spec / Plan / Implement。

## 通过标准

- 已直接回答用户问题。
- 关键结论有文件、行号、来源或日志支撑。
- 已记录证据缺口和未验证项。
- 未超出只读授权。
