# 任务交接

工作流决定何时交接，CLI 汇总当前事实，执行者说明决策依据和准确的续接位置。具体任务的数据保存在任务文件中，不写入本 Skill。

## 自然语言入口

用户只需说“交接当前任务”或“继续上次任务”。整理文件、运行命令、检查状态由 Agent 完成；不要把内部步骤清单交给用户执行。

- 准备交接时使用 `agent-workflow task prepare`，恢复时使用 `agent-workflow task continue`。若当前会话已知任务 ID，附 `--task <task-id>`；否则由 CLI 选择最近未完成任务。
- 若已由上述入口加载本 Skill 和任务摘要，直接执行对应操作，不重复调用入口。选定后固定使用返回的任务 ID，避免期间其他任务活动导致目标切换。
- 多个任务同样最近时，只询问一次任务选择，可展示任务名和阶段，不要求用户查找路径。需要结构化候选时运行 `agent-workflow task current --format json`。
- 无本地任务但当前会话有完整事实时，按原任务路由创建最小必要的任务记录，再准备交接。不要向用户索要可以从会话或现有文件获得的信息。
- 交接成功后简短说明已保存的停点和下一步；恢复时核对后直接继续，不只返回一份操作指南。缺少外部环境或必要决策时才说明具体阻塞。

## 准备交接

1. 运行 `agent-workflow task summary --task <task-id>`。读取相关阶段产物和任务 diff，核实实际完成的工作。使用 `--section <file>#<section>` 展开摘要中延后的上下文，或使用 `--format json` 获取完整结构化摘要。迁移旧交接文档时，先将仍适用的决策、上下文和授权来源整理到 notes 或对应的原始产物中，再生成替代文档。
2. 在任务目录中按下述章节编写 `handoff-notes.md`，明确区分事实、假设和计划。当没有决策、失败尝试或阻塞时，可以写 `none` 并说明原因。不得编造进度或授权。
3. 运行 `agent-workflow task handoff --task <task-id>`，再运行 `agent-workflow task handoff-check --task <task-id>`。修复缺失内容、失效的证据引用或过期事实。生成的 `handoff.md` 和 `handoff-state.json` 分别是阅读视图和新鲜度记录；需要修改时，先更新 notes 或原始产物，再重新生成。

notes 必须包含以下章节。章节名是 CLI 解析契约，保留英文原名，正文使用中文：

- `## Checkpoint`（当前检查点）：准确的停止位置、尚未确认的事项、环境前提，以及本任务改动与原有改动的边界。
- `## Decisions`（决策依据）：已选方案、证据、相关的已排除方案，以及需要重新评估的条件。
- `## Attempts / Unknowns`（尝试与未知项）：尝试过的路径和实际失败结果、未证实的假设、阻塞及其解除条件。避免写成按时间排列的流水账。
- `## Next Steps`（接手步骤）：按顺序记录动作、执行位置、预期结果和停止条件。第一步必须能直接执行；任务已完成时，记录完成证据和明确延后的工作。
- `## Required Context`（必读上下文）：使用反引号标记任务相对文件路径，可附准确的章节名，例如 `spec.md#Design`，并说明阅读原因。证据应保存在本地且可迁移；代码位置在正文中用仓库标识和相对路径描述。

接手步骤示例：在 manifest 声明的仓库中，按验证契约的步骤执行 VT2。预期空输入不会触发下游调用；如果调用次数不为零，保留输出，不得将 Verify 标记为完成。

自动生成的事实已包含生命周期、范围、授权记录、仓库指纹和验证结果。notes 应说明这些事实对后续工作的影响，避免重复抄写记录。历史验证通过，不代表当前 patch 已通过验证。

## 恢复任务

1. 运行 `agent-workflow task summary --task <task-id>`。对于新生成的交接包，执行动作前先运行 `agent-workflow task handoff-check --task <task-id>`。旧交接文档可以读取，但没有经过验证的新鲜度基线。
2. 根据当前仓库事实和任务产物，逐项处理检查报告中的差异。不得仅为清除过期警告而重新生成；应先重新评估受变化影响的决策和验证结果。继续执行前，展开摘要中延后的关键章节。
3. 执行第一条适用的接手步骤，再使用 `agent-workflow next --task <task-id>` 回到任务原有路由。处于 blocked 状态的阶段必须通过任务生命周期命令解除阻塞。将新证据写入对应产物，续接位置变化时更新 notes。

授权条目是待核对的记录，需要与适用的用户授权和工具策略保持一致。条目缺失或相互冲突不构成授权。不得从交接文档推断 stage、commit、push 或发布操作已获批准。
