# Implementation Approval Card

业务写入前提交 Implementation Review：

- 根因/依据：缺陷区分直接原因与设计根因；需求说明动机与不变量；附证据和未知项。
- 责任层/修改：说明归属和理由；列出 Repository、File / Symbol、最小完整语义闭环、兼容和 OOS。
- 维护/验证：对比表象补丁；检查重复规则/状态、复用边界、一个同类或后续扩展场景、空值/异常/旧数据，并列出 AC / VT、预期和缺口。

只过当前案例、增加特判、责任层不明或缺少同类/边界场景时不得批准；涉及公共链路、接口、数据模型或扩围时升级 Standard Change。

标记“等待用户批准”并结束回合，不得写业务文件。仅当前会话明确同意后可使用
`--user-approved`；提问、沉默、历史批准或 Agent 判断无效。上述内容变化须重新确认。
