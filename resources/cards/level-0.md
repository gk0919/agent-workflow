# level-0 Card（L0）

L0 只处理**纯外观改动**：样式、文案、格式。出现任何行为变化即离开 L0。

## 声明要求

- 必须显式声明 `--level 0`；缺少声明或声明其他等级一律拒绝，不接受"沉默即默认 L0"。
- 变更类型必须是 `cosmetic`，且通过 Micro 门禁数值与风险标识检查。
- 事实推导等级高于声明等级时确定性拒绝；按错误信息升级，不要重试同一声明。

## 最简 Brief

沿用 Brief，只填与外观相关的项：

- G：要变成什么样，一句话。
- AC：可见判定，能截图或能跑的检查项。
- OOS：明确不碰的行为、接口和数据。
- C：责任层与最小完整修改，写到文件 / 符号。
- VT：验证项与预期。

## 边界

- 无行为变化、无接口 / 数据 / 权限变更、无新状态，单仓库小 diff。
- UI 语义不明确、需要在多个方案里取舍时升级，不在 L0 猜。
- 越界立即升级到 `level-1`（L1）或 `level-2`（L2/L3），保留已确认事实。
- 不得"只过当前案例"或加特判；外观改动不得顺手改行为。

## 停止点

提交 Brief 后标记"等待用户批准"并结束回合；仅在当前会话用户明确同意后使用
`--user-approved`。
